# Neon Getaway — Godot source

This is the source for the Godot 4.5.2 game embedded at `/arcade/demo` and `/arcade`. It starts with a story race across a fictional coastal district: meet Milo, talk, enter the Panther GT, pass seven gates from the city to the forest within about three minutes. At the finish, press E for the original car-heist delivery chapter. The public `Web Demo` export lives in `public/arcade-godot/` and retains one delivery contract; the protected `Web Pro` pack in `game/godot/pro-web/` retains three. Re-export both variants after changing either scene or GDScript. The HUD supports `lang=en|es|pt-BR|nl`.

First run `python game/godot/fetch_character.py` from the repository root. This fetches a pinned, checksum-verified animation-bearing GLB locally. Its raw Mixamo clips are excluded from Git; only the compiled game is distributed. Then open `project.godot` in Godot 4.5.2 and run the main scene. Controls: WASD or arrows to move/drive, E to talk/enter/continue, Space to brake, Shift for handbrake while driving, M to open the original delivery missions at any time, R to restart. The race timer starts only after entering the car. The district has pedestrians with simple role-based routines, moving traffic, a city, highway, broad forest, marina and stylized water. The original delivery chapter remains in `scenes/heist.tscn` and now inherits the same coastal world through `scripts/heist_world.gd`; its three named contracts, 165-second clock and scoring remain. This is still a prototype: the city and NPC schedules are simplified, the finite 2.1 km map is not a GTA-scale open world, driving physics are arcade-like, and there is no spoken dialogue, sound design, mobile controls or globally verified leaderboard.

Both chapters use CC0 VitruvianGodot body/head meshes and downscaled textures; the archived first prototype used [GDQuest's Open 3D Mannequin](https://github.com/gdquest-demos/godot-3d-mannequin) under CC BY 4.0. Car meshes are from Kenney's Car Kit 3.1 under CC0. Road and grass textures are CC0 Poly Haven assets. Names, missions and environment layout are original. See `assets/ATTRIBUTION.md`. The Godot AI editor add-on came from the user-provided archive and is MIT-licensed; it is excluded from Web exports.

Godot AI MCP is enabled locally in Codex via `uvx` and was verified against a live Godot 4.5.2 editor (`editor_state` returned ready). Portable Godot, `uvx`, server logs and export templates live in ignored `.tooling/` in the repository root. On a different computer, install Godot 4.5.2, its Web export templates, and [godot-ai](https://github.com/hi-godot/godot-ai) separately. The MCP registration points to this machine's `.tooling` path and is not portable.

For a local export, use the `Web Demo` preset to `public/arcade-godot/index.html` and the `Web Pro` preset to a temporary directory. Copy only the resulting Pro `index.html` and `index.pck` to `game/godot/pro-web/`. The protected route serves the common engine files from the public export. The project uses the GL Compatibility renderer and non-threaded Web template so the page can be embedded without cross-origin isolation. The 38 MB WebAssembly runtime is a material download for mobile visitors.

The browser leaderboard is local and unverified. The Pro package is behind a server subscription check, but any shipped game client can be modified by a determined player. Do not use local scores for prizes or public rankings. A global leaderboard requires server-authoritative scoring and abuse controls.

The circular north-up minimap reads the actual street/building registry and actor positions in both chapters. CharacterBody3D collision handles walls, trees, pumps and vehicles; vehicle impacts use actual travel, include a brief knockdown and a capped ground stain. Shared vehicle handling adds acceleration, braking before reverse, speed-dependent steering, lateral grip and a separate handbrake. Car exits check capsule clearance and actual planar speed. Walking follows the camera bearing; drag with the right mouse button to orbit, with automatic camera follow while driving. Pedestrians visit shops via marked crossings, wait for approaching cars and rest after closing hours; traffic yields and follows parked cars. These remain simplified routines rather than a full simulation of human behavior.

The 16-minute day/night cycle drives the sun, sky and street-lamp glow. Shops, a fuel station, market and residential/dock districts expand the city. Static meshes sharing a material are merged within 150 m tiles. Distant human visuals, animations and shadows are reduced without disabling actor physics. The render budget automatically adjusts resolution, mesh LOD and shadow distance from active rendered-frame samples, with warmup and hysteresis; canvas HUD text retains native resolution. The Compatibility renderer uses bilinear scaling and only supported antialiasing. Append `&perf=1` to an export's language query for an optional QA overlay with measured frame intervals. Normal play has no quality selector or overlay. Performance depends on the GPU, browser, presentation and viewport; no universal frame-rate guarantee is made.

[OpenWorldJS](https://github.com/obecerra3/OpenWorldJS) was reviewed for chunking, instancing and collision architecture. Its code/assets were not copied (no root license was visible); the implementation remains native Godot. Run the behavior checks with `godot --headless --fixed-fps 60 --path game/godot --script res://tests/story_smoke.gd`. They exercise conversation/entry, movement orientation, wall sliding, impacts, minimap coordinates, day/night and a complete timed race into the original mission scene. The race route test removes ambient traffic to isolate route/timer reachability; this is not a performance benchmark.

Additional physics/behavior suites are `city_behaviour_test.gd`, `heist_world_test.gd`, `vehicle_handling_test.gd` and `render_budget_test.gd` in the same tests directory. Run each with the same command and its script name. They check crossing/traffic interactions, impulse-only parked-car impacts, safe exits, sideways-speed gates, original mission scoring and failure, actual body/wall handling, and adaptive-render policy without allowing visual culling to disable collision.
